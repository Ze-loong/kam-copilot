# 12-数据字典

> 定义 KAM Copilot 的业务数据口径：客户画像字段、标签体系、组织与权限维度、商机订单、演示数据。
> 代码中的字段白名单、前端标签文案、mock 数据都以本文件为准。

## 一、业务背景

恒创智能装备集团（虚构）是一家工业自动化解决方案提供商，大客户销售顾问通过企业微信对接制造企业客户，业务分两类：

| 场景 | 客户 | 信息来源 | 系统能力 |
| --- | --- | --- | --- |
| 新客方案沟通 | 尚未成交的制造企业 | 产品与解决方案目录、标杆案例 | 画像、回复建议、标签推荐 |
| 老客技改扩容 | 已成交、有维保关系的客户 | 历史订单、维保记录、微信客服对话 | 画像、客服回复建议、复购机会识别 |

"客户"在系统里指**对接人**（一个企业微信外部联系人），画像描述的是"这位对接人 + 他所在企业"的情况。

## 二、客户画像字段（12 个）

每个字段独立生成、独立确认（F01），结构为 `{value, confidence, source, status}`。字段之间刻意不设依赖——任何一个字段被确认/放弃，都不影响其他字段。

**字段性质决定置信度规则：**
- **事实类**：客观信息。前后说法直接冲突 → 低置信度。
- **目标类**：客户想要什么。方向发生变化且客户没解释原因 → 按矛盾处理，低置信度。
- **行为类**：客户的行为倾向。"问过"不算证据，必须有明确反应（表态、成交、放弃）才算。

| 分组 | 字段 key | 中文名 | 性质 | 取值示例 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 企业基础信息 | `company_name` | 所属企业 | 事实 | 苏州联拓汽车零部件有限公司 | |
| | `company_scale` | 企业规模 | 事实 | 约 800 人，年产值 6 亿 | |
| | `production_status` | 主营产品与产线现状 | 事实 | 车身冲压件，3 条焊装线，半自动，主要依赖人工点焊 | |
| 技改需求 | `project_stage` | 技改项目阶段 | 事实 | 已立项，预计 Q1 招标 | **见第三节"阶段推进陷阱"** |
| | `pain_points` | 核心痛点 | 目标 | 焊点一致性差导致返修率高；招工难 | |
| | `tech_goal` | 技改目标 | 目标 | 焊装线节拍从 60s 降到 45s | 方向变化需有原因 |
| | `budget_range` | 预算区间 | 事实 | 300–500 万 | 只采信客户明确说出的数字或区间 |
| 决策链 | `decision_makers` | 决策链 | 事实 | 设备部经理提需求，生产副总把技术关，董事长拍板 | |
| | `decision_style` | 决策风格 | 行为 | 招标流程驱动，重视资质与案例 | |
| | `price_sensitivity` | 价格敏感度 | 行为 | 较高：明确表示超过 400 万需重新报批 | 只问价不表态 = 无证据 |
| 沟通与竞争 | `reply_time` | 活跃沟通时段 | 行为 | 工作日上午，周末基本不回 | |
| | `competitor_info` | 竞品接触情况 | 事实 | 同时在接触两家本地集成商 | |

## 三、两个关键设计判断

### 1. 阶段推进陷阱（`project_stage`）

技改项目阶段会随时间**自然推进**（调研 → 方案 → 立项 → 招标 → 签约），看起来前后说法不同很正常。但它也会**倒退或停滞**（预算被砍、项目搁置、换了负责人）。

所以规则是：
- 两条证据阶段不同时，**必须有明确的推进事件**（如"立项批下来了""招标文件已挂网"）才能采信较新的一条；
- 没有推进事件、只是说法变了 → 低置信度（0–3），source 写明冲突；
- 阶段**倒退**（例如先说"已立项"、后说"还在做可行性调研"）→ 一律低置信度，source 标注"疑似项目搁置或信息有误"。

不能因为"新证据时间更晚"就默认它是正常推进——模型无法从聊天记录判断项目真实进度。

### 2. 放画像还是放标签

同一条信息两边都能放，判断标准是**用途**：

| | 画像字段 | 标签 |
| --- | --- | --- |
| 回答的问题 | "这个客户具体是什么情况" | "这个客户属于哪一类" |
| 形态 | 自由描述 + 置信度 + 证据来源 | 预定义枚举，打上/不打 |
| 用途 | 顾问沟通前看懂客户 | 筛选、分群、看板统计、批量运营 |
| 会被推翻吗 | 会，需要逐字段确认 | 会，按标签增删 |

因此：**价格敏感度**需要程度描述和证据链 → 画像；**所属行业**是离散分类、用于筛选和看板 → 标签。画像里不重复放行业，标签里不放价格敏感。

## 四、标签体系（6 组 29 个）

| 标签组 | 选择方式 | 标签 |
| --- | --- | --- |
| 所属行业 | 单选 | 汽车零部件、3C 电子、新能源（锂电/光伏）、工程机械、家电、食品饮料、医疗器械 |
| 企业类型 | 单选 | 国央企、民营上市、民营中小、外资/合资 |
| 需求方向 | 多选 | 产线自动化改造、机器人工作站、视觉检测、MES/数字化、仓储物流自动化、设备维保 |
| 意向等级 | 单选 | 高意向、中意向、低意向、暂无需求 |
| 客户价值 | 单选 | 战略大客户、重点客户、普通客户、老客复购 |
| 关注重点 | 多选 | 关注交付周期、关注技术方案、关注售后响应、关注投资回报 |

"单选/多选"是业务口径：单选组同一客户只应有一个标签，推荐新增时应同时建议移除同组旧标签。

## 五、组织与权限

| 维度 | 取值 |
| --- | --- |
| 角色 | `consultant` 大客户销售顾问 / `regional_manager` 大区总监 / `super_admin` 超级管理员 |
| 区域 | 华东、华南、华北（超管为"全国"） |

权限 = 角色 × 区域：顾问只看自己名下客户；大区总监看本大区所有顾问及其客户；超管看全部。顾问无权访问管理看板。

## 六、商机与订单

原"订单"结构不变，业务含义为**技改方案 / 设备采购 / 维保合同**。示例商品名：
- 焊装线机器人工作站（2 台六轴机器人 + 变位机）
- AOI 视觉检测系统（2 工位）
- 仓储 AGV 调度系统一期
- 产线 MES 一期（生产报工 + 设备联网）
- 年度设备维保合同（含 2 次巡检）
